# GitHub Profile Setup — Psycall

## Objetivo

Este guia explica como transformar o material de perfil preparado neste diretório em um **perfil GitHub profissional, consistente e pronto para causar boa impressão pública**. O objetivo não é apenas preencher a página do usuário, mas posicionar a conta como uma extensão natural da visão do **Pocket Oracle**.

## Como funciona o README de perfil no GitHub

O GitHub exibe automaticamente um README especial quando existe um repositório **público** com o mesmo nome do usuário. Portanto, para o perfil `psycall`, o repositório correto deve se chamar **`psycall`** [1]. Depois disso, o arquivo `README.md` desse repositório passa a aparecer no topo do perfil.

## Estrutura recomendada

| Arquivo | Finalidade |
| --- | --- |
| `README.md` | Texto principal do perfil, em formato bilíngue e com posicionamento profissional |
| `PROFILE_SETUP.md` | Guia de publicação e manutenção |
| `assets/` | Espaço opcional para imagens específicas do perfil |

## Passo a passo de publicação

Primeiro, crie um novo repositório público chamado **`psycall`** na sua conta do GitHub. Em seguida, copie o conteúdo do arquivo `profile/README.md` deste projeto para o `README.md` do novo repositório de perfil. Se quiser manter o banner com carregamento mais confiável, adicione também uma cópia de `psycall-dev-banner.png` dentro do repositório de perfil e atualize o caminho da imagem para um arquivo local do próprio repositório.

Depois disso, revise a renderização pública do perfil e confirme se o banner aparece corretamente, se os textos em português e inglês estão legíveis e se o link ou menção ao **Pocket Oracle** está coerente com o posicionamento atual do projeto.

## Ajustes visuais recomendados

| Ajuste | Motivo |
| --- | --- |
| Usar banner próprio no repositório de perfil | Evita dependência de caminho relativo entre repositórios |
| Manter tom bilíngue | Amplia o alcance para parceiros internacionais |
| Evitar excesso de badges | Preserva aparência premium e menos poluída |
| Priorizar narrativa | Faz o perfil parecer mais maduro e menos genérico |
| Atualizar repositórios em destaque | Reforça o projeto principal e futuras provas de execução |

## Texto curto de bio sugerido

A bio da conta deve complementar o README, não competir com ele. Uma versão simples, forte e profissional pode seguir esta linha:

> Founder & developer building agentic AI systems, mobile-first products, and real-world automation infrastructure.

Uma alternativa em português com tom forte seria:

> Fundador e desenvolvedor de sistemas agentic, produtos mobile-first e infraestrutura de automação com IA.

## Campos públicos recomendados

| Campo | Recomendação |
| --- | --- |
| Name | `Psycall` ou seu nome profissional principal |
| Bio | Curta, técnica e orientada a produto |
| Company | Nome atual da iniciativa, se desejar tornar público |
| Location | Opcional, apenas se fizer sentido estratégico |
| Website | URL do projeto ou landing page futura |
| Social links | Apenas os que reforçam reputação e continuidade |

## Rotina de manutenção

O perfil deve ser atualizado sempre que houver mudança relevante no posicionamento do projeto principal, novo lançamento, milestone pública ou evolução importante da tese de produto. O ideal é que o perfil funcione como uma **camada estável de narrativa**, enquanto os repositórios aprofundam os detalhes técnicos.
