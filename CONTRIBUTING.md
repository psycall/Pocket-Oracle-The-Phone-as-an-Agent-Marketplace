# Contribuindo

Obrigado por contribuir com o Pocket Oracle. Este repositório segue um padrão de engenharia orientado a produto, segurança e clareza operacional. Toda contribuição deve chegar com contexto, justificativa e impacto esperado.

## Fluxo recomendado

| Etapa | Expectativa |
| --- | --- |
| Planejamento | Abra uma issue ou descreva a motivação no PR |
| Branch | Use `feat/...`, `fix/...`, `docs/...` ou `chore/...` |
| Commit | Use mensagens objetivas no padrão convencional |
| Revisão | Explique riscos, dependências e mudanças de comportamento |
| Segurança | Verifique que nenhum segredo foi incluído |

## Convenção de commits

Exemplos recomendados:

```text
feat: add geoproof payment middleware
fix: validate x-payment-authorization header
docs: improve submission checklist
```

## Qualidade mínima

Antes de abrir PR, valide se a mudança mantém a coerência da narrativa do produto, não quebra o fluxo de monetização e preserva a postura profissional do repositório.
