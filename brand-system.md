# Orvion — Brand System

## Objetivo

Este documento consolida a identidade visual do **Orvion** para que o projeto mantenha uma apresentação coerente em README, perfil do fundador, demos, pitches, releases e futuras superfícies de produto. Em projetos de alto potencial, branding não é ornamento; branding é uma camada de **confiança, lembrança e clareza estratégica**.

## Princípio de marca

A identidade do Orvion deve transmitir quatro ideias ao mesmo tempo: **inteligência agentic**, **presença mobile**, **prova do mundo físico** e **credibilidade técnica premium**. Toda aplicação visual deve reforçar essa combinação. Se a peça parecer genérica, futurista demais sem utilidade, ou bonita sem comunicar produto, ela está fora do padrão.

| Pilar visual | Significado estratégico | Sinal percebido |
| --- | --- | --- |
| Inteligência agentic | O sistema toma decisões e solicita verificações | Produto alinhado ao futuro da IA aplicada |
| Smartphone como interface | O celular é a peça central da tese | Experiência concreta e distribuída |
| Verificação física | O projeto conecta software e realidade | Valor prático e não apenas conceitual |
| Estética premium | A execução parece séria, limpa e memorável | Confiança imediata de parceiros e empresas |

## Direção estética

A linguagem visual deve seguir uma estética de **startup infra-first com polimento de produto**. Isso significa evitar excesso de efeitos gratuitos, ruído visual e complexidade ornamental. A marca deve parecer preparada para conversar com desenvolvedores, compradores corporativos e avaliadores de inovação.

| Dimensão | Diretriz |
| --- | --- |
| Cores | Usar paleta escura com pontos de luz contrastantes e sensação de precisão |
| Tipografia | Títulos fortes, corpo limpo e leitura rápida |
| Composição | Foco em clareza, profundidade moderada e hierarquia evidente |
| Metáforas | Rede, sensor, fluxo econômico, verificação, sinal confiável |
| Tom visual | Futurista, porém utilitário; sofisticado, porém técnico |

## Regras de uso

Para manter consistência pública, toda nova peça deve seguir regras simples e firmes.

| Regra | Aplicação prática |
| --- | --- |
| Não distorcer logotipo | Preservar proporção, margens e legibilidade |
| Não usar fundos poluídos | Priorizar contraste alto e leitura rápida |
| Não inventar novas variações sem registro | Toda expansão deve ser adicionada a este documento |
| Priorizar o social preview oficial | Garantir consistência em compartilhamentos do GitHub |
| Usar banner do fundador como derivação da marca | O perfil pessoal deve parecer extensão do produto |

## Aplicações prioritárias

A marca atual deve ser aplicada primeiro nas superfícies que geram maior retorno público imediato.

| Superfície | Prioridade | Objetivo |
| --- | --- | --- |
| Repositório GitHub | Alta | Melhorar primeira impressão |
| README principal | Alta | Reforçar narrativa de startup séria |
| README de perfil | Alta | Unificar fundador e projeto |
| Pitch deck futuro | Média | Apoiar storytelling comercial |
| Landing page | Alta | Converter curiosidade em interesse real |
| Demo em vídeo | Média | Criar memorabilidade visual |

## Evolução recomendada

A próxima camada de branding deve expandir a identidade atual sem romper o sistema já criado.

| Próximo asset | Ganho esperado |
| --- | --- |
| Lockup horizontal dark/light | Mais flexibilidade para páginas e documentos |
| Pack de screenshots guiadas | Melhor percepção de produto vivo |
| Architecture hero artwork | Melhor narrativa para README e deck |
| Motion bumper curto | Mais força para vídeos e teasers |
| Visual standards for UI | Coerência entre marca e telas do produto |

## Conclusão

Um branding forte não substitui produto, mas acelera compreensão, aumenta confiança e faz o projeto parecer maior, mais organizado e mais memorável. No caso do **Orvion**, a marca precisa sempre comunicar a mesma ideia: **IA que consegue ver, confirmar e operar no mundo real por meio do smartphone, com lógica econômica clara e apresentação de nível profissional**.
